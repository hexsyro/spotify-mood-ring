----------------------------------------------------------------
⚠️ DATA FEASIBILITY NOTE — READ THIS BEFORE YOU START SCRAPING
----------------------------------------------------------------
The original idea of scraping "Spotify weekly charts" directly is
NOT achievable with requests + BeautifulSoup. Spotify's charts
pages (charts.spotify.com) are built with a JavaScript framework
(React) that fetches data from a private, authenticated internal
API after the page loads. BeautifulSoup only sees the raw HTML
Spotify's server sends BEFORE JavaScript runs — for a page like
this, that raw HTML is nearly empty (a `<div id="root"></div>`
with no chart data inside it). This is called client-side
rendering, and it's the single most common reason a scraping
project quietly returns nothing. You cannot fix this by changing
your BeautifulSoup selectors — the data genuinely is not in the
HTML you're allowed to fetch with a simple GET request.

THE FIX — same skills, an achievable target:
Scrape Wikipedia's "Billboard Year-End Hot 100 singles" pages
instead (e.g. https://en.wikipedia.org/wiki/Billboard_Year-End_Hot_100_singles_of_2023).
These are plain, server-rendered HTML tables — no JavaScript
needed, no login, no rate-limit tricks, and one page per year
going back decades. You'll scrape one page per year instead of
one page per week, which is actually a friendlier project for a
first scraper: fewer requests, more stable structure.

For "mood" data (valence, energy, tempo, danceability) you were
always going to need audio features that aren't scrapable from
any public webpage anyway — Spotify only exposes those through
its authenticated API. Use a pre-downloaded Kaggle dataset of
Spotify audio features instead (search Kaggle for "Spotify
tracks dataset" or "Spotify audio features") — download the CSV
once, place it in data/raw/, and join it to your scraped chart
data by song title + artist name. This join will be imperfect
(different spellings, "feat." formatting, etc.) — cleaning that
up is itself a real, useful exercise, not a shortcut.

SECTION 1 — PYTHON FUNDAMENTALS (FUNCTIONS, CONTROL FLOW)
----------------------------------------------------------------
GOAL: Build small, single-purpose functions for fetching and
parsing pages, before worrying about the full dataset.

STEPS:
1. Open notebooks/01_scrape_explore.ipynb.
2. Fetch ONE Wikipedia year page with requests.get(url) and
   print response.status_code — confirm it's 200 before doing
   anything else.
3. Write a function parse_year_page(html, year) that takes the
   raw HTML and a year, and returns a list of dicts like
   {"year": year, "rank": ..., "title": ..., "artist": ...}.
   Use BeautifulSoup to find the correct <table> (Wikipedia
   tables usually have class "wikitable") and loop over its
   <tr> rows.
4. Wrap the fetch in a function fetch_year(year) that builds the
   URL from the year, adds a time.sleep(1) delay, and calls
   requests.get(). Add a try/except so one failed year doesn't
   crash the whole run — on failure, print a warning and return
   None instead of raising.
5. Test fetch_year(2023) and parse_year_page() together on one
   year before looping over many.
6. Once both functions work correctly on one year, cut them out
   of the notebook and paste them into src/scraper.py.

SELF-CHECK:
[ ] parse_year_page() returns a list of dicts, not a DataFrame
    (keep DataFrame construction in the notebook, not in this
    function — it's more reusable this way)
[ ] fetch_year() does not crash the notebook if a year is missing
    or the request times out
[ ] Both functions live in src/scraper.py and can be imported
    with `from src.scraper import fetch_year, parse_year_page`

DONE WHEN: you can call fetch_year(2023) and parse_year_page()
from a fresh notebook cell after `import src.scraper` and get a
correct list of ~100 songs back.

SECTION 2 — DATA EXTRACTION (WEB SCRAPING, MULTIPLE YEARS)
----------------------------------------------------------------
GOAL: Scrape a full range of years into raw, unprocessed files.

STEPS:
1. Still in notebooks/01_scrape_explore.ipynb, write a loop that
   calls fetch_year() for every year in your chosen range (e.g.
   2010–2023).
2. After each year's HTML is parsed, save that year's raw parsed
   list as its own file: data/raw/year_2010.json,

   end.

   already exists — if it does, skip it. This makes your scraper
   safely resumable if it's interrupted partway through.
4. Add a print statement after each year finishes so you can see
   progress (e.g. "2015: 100 songs scraped").

SELF-CHECK:

SECTION 6 — NUMPY VECTORIZED OPERATIONS
----------------------------------------------------------------
GOAL: Use array math (not loops) to find trends and outliers.

STEPS:

   z = (arr - arr.mean()) / arr.std() — do NOT use a loop.

   songs — (moods far outside the norm for their era).
5. Build a correlation matrix across valence, energy, tempo, and
   danceability using np.corrcoef(), and print it as a labeled
   DataFrame for readability.
6. Make one plot: rolling average valence over time (matplotlib
   is fine — a simple line chart).
